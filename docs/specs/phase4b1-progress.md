# Phase 4B-1 진행 기록

- SDD·영향 분석: 완료. Phase 4A Reasoner 인터페이스를 유지하고 모델 출력은 추가로 엄격한 스키마와 기존 그래프의 후보·근거·관측값 검증을 거친다. 공급자·모델·코드 버전·요금·각 한도는 실행별 필수 입력이며 운영 기본값은 없다.
- 구현: `LLMReasoner`와 `ModelBroker`/`Provider` protocol, 동일 프로세스용 `OfflineBroker`, I/O가 없는 `FakeProvider`를 추가했다. Pydantic 스키마는 추가 필드, 잘못된 타입, 중복 JSON 키, NaN 및 허용되지 않은 조회를 거부한다. 모델에는 CaseContext와 검증된 Observation, 역할 지침 및 스키마만 전달한다.
- 예산: 호출 수, 입력·출력·누적 토큰, 누적 비용, 동시 호출, 재시도 및 호출당 출력 상한과 시간 제한을 명시해야 한다. 사전 입력 상한과 최대 출력의 비용을 잠금 아래 예약한다. 승인된 그래프 도구/반복 한도를 넘는 실행은 시작하지 않는다. 확인된 사용량은 실패·재시도에도 누적한다. 사용량이 없거나 초과·비정상이면 broker를 차단한다. 사용량이 확인된 `retryable` 오류만 정해진 횟수 내에서 재시도한다.
- Synthetic 검증: Fake Provider로 정상 흐름, 비인가 셸 요청·프롬프트 인젝션, 중복 키·스키마 오류, 토큰/비용/호출 한도, 동시 예약, 재시도, 시간 초과, 불명 사용량, 오류 traceback 비공개 및 공개 보고서 allowlist를 확인했다. 실제 모델·정답·API는 사용하지 않았다.
- 격리 확인: 별도 macOS `sandbox-exec` 시험에서 네트워크·파일 쓰기를 차단하고 사용자 디렉터리에서 프로젝트 소스와 의존성만 읽도록 설정한 Fake Broker는 정상 실행됐으며, 평가자 전용 매핑 파일 읽기는 권한 오류로 거부됐다. 이는 해당 로컬 환경 시험이며 제품용 외부 Broker가 완성되었다는 뜻이 아니다.
- 미완료·진입 차단: 외부 API 연결·네트워크 허용 broker·OS 권한 강제·인증된 프로세스 간 통신은 설계만 했고 구현하지 않았다. 현재 `OfflineBroker`는 같은 Python 프로세스의 신뢰된 객체로서 정답 접근을 스스로 차단하지 못한다. 실제 Provider를 연결하기 전 Agent와 Broker를 별도 격리하고 Broker에 정답/매핑/키 마운트와 자격 증명을 전달하지 않는 설정을 별도로 구현·검증해야 한다. 기본 네트워크 차단 실행과 모델·가격·한도·보존 정책의 사용자 결정도 필요하다.
- 한계: 사전 입력 토큰 상한과 요금표·제공자 사용량이 정확하고 보수적이어야 비용 예약이 유효하다. 타임아웃 시 사용량을 알 수 없어 재호출을 차단하지만 Python 스레드는 강제 종료되지 않으므로 백그라운드 작업과 청구가 이어질 수 있다. 실제 과금 초과를 보장 차단하거나 외부 제공자의 취소를 보장하지 않는다. 하드 종료 및 정산은 격리된 실제 Broker의 필수 과제다. 동시성/예산 원장은 공유 인스턴스의 단일 프로세스 범위이며 다중 프로세스 전역 제한이 아니다. 텔레메트리 명령은 비신뢰 데이터로 취급하고 스키마를 검증하지만 prompt injection을 완전히 막거나 의미적 인과성을 검증하지는 못한다.

- 2026-11-11 최종 로컬 검증: `UV_OFFLINE=1 make check` 및 `UV_OFFLINE=1 make harness-verify` 각각 120건 통과. 동시 요청 중 사용량이 불명확해지면 다른 진행 중 요청의 결과도 허용하지 않도록 회귀 검증했다. 실제 모델 호출과 20건 정확도 평가는 하지 않았다.

- 코드 리뷰에서 만료된 deadline에서도 Provider 작업이 시작될 수 있는 경계 조건을 수정하고, 시작되지 않음을 회귀 시험했다.
