# RCA Agent v0.1 SDD 명세

상태: **부분 확정** (2026-11-04). 사용자가 확정한 범위와 아래 불변 조건은 설계 기준이다. 미정 항목 및 그에 의존하는 실행·수락 판정은 확정되지 않았다. Phase 1 데이터 준비만 승인되었으며 실제 모델 호출 및 유료 평가는 금지한다. v0.0의 계약·테스트·CI는 유지한다.

## 목표와 제외 범위

- 블라인드 장애 관측 자료를 조사해 허용된 후보를 근거와 함께 순위화하고 분석 과정과 실패를 재현 가능하게 기록한다.
- LangGraph의 조사 → 가설 생성 → 증거 검증 → 순위화 흐름과 로그·메트릭·트레이스 조회 인터페이스를 설계한다. Phase 1에서는 데이터 준비만 구현하며 그래프와 모델 호출은 구현하지 않는다.
- 상시 서버와 유료 인프라를 두지 않는다. 실제 LLM 호출은 별도로 명시 실행할 때만 가능하다. 기본 테스트와 GitHub Actions의 검증 단계는 모의 객체 기반 오프라인으로 유지한다. 설치 단계의 네트워크는 별개다.
- RCA 정확도 목표, 공급자·모델, 실행 예산과 도구 횟수, 데이터 보관·삭제 기간은 미정이다. 모델은 향후 외부 설정으로 주입 가능하게 설계하며 기본 모델이나 LLM 호출은 Phase 1에 없다. 정책값을 코드 기본값으로 간주하지 않는다.

## 현재 하네스와 호환성

현재 `RCAInput`은 case_id, 후보 및 evidence를 포함하며 `RCAResult`는 순위별 후보·설명·evidence ID 및 도구 호출 이력을 요구한다. 고유 ID, 허용 후보, 잘못된 JSONL을 거부한다. 현재 타입은 조사 중 생성된 evidence의 반영, 세부 provenance, 실패·중단 결과를 표현하지 못하고, 원래 입력에 없던 evidence ID를 결과에서 거부한다. v0.1에서는 **최종 검증 시** 원본 입력과 같은 case에서 성공한 도구 호출로 만들어진 evidence를 합친 검증용 RCAInput을 사용하고 원래 입력을 변경하지 않는 어댑터를 설계한다. 그래프 내부 증거 등록과 검증용 입력이 일치해야 한다. 기존 `RCAResult.parse`의 계약은 약화하지 않는다. 증거가 없거나 중단된 경우 정상 `RCAResult`를 위조하지 않고 별도의 실패 envelope로 분리한다. v0.0 코드는 변경하지 않았다.

## RCAEval 데이터와 20건 평가

확정: RE2-OB 20건을 장애 유형별 3~4건으로 배분하고 서비스 편중을 줄인다. 2026-11-09 결정에 따라 이전 공개 seed 42 표본과 겹치지 않는 새 표본을 평가자 전용 256-bit 무작위 키로 생성한다. 같은 비공개 키와 고정 데이터 리비전으로 표본 및 두 종류의 독립적인 익명 ID를 재현할 수 있다. 키와 사례 매핑은 평가자 전용이고 영구 보존·삭제 정책은 미정이다. 기존 공개 manifest와 평가 기록은 과거 이력일 뿐 더 이상 블라인드 평가로 사용할 수 없다.

블라인드 export는 사례마다 비공개로 시간 이동해 공개 인덱스의 어떤 주입 시각과도 같지 않게 하고, 상대 시간과 메트릭 수치를 유지한다. trace/span/parent ID는 사례별 가명으로 바꾸고, 로그의 지정된 시각·UUID·IPv4·이메일·긴 16진수/숫자 패턴을 마스킹한다. trace의 사람이 읽는 `time` 컬럼은 제거 대신 `[redacted]`로 바꾼다. 이 조치는 알려진 선택규칙·시각·식별자 경로를 줄이지만, 공개 원본과 메트릭·로그 내용을 대조하는 지문 공격이나 마스킹 패턴 밖의 식별자를 막지는 못한다. `--network none`과 데이터·정답을 분리한 컨테이너 경계가 필수이며, 사전 지식까지 차단한다고 주장하지 않는다.

2026-11-04 공식 [Hugging Face 데이터셋](https://huggingface.co/datasets/phamquiluan/RCAEval)의 데이터셋 뷰어 API에서 735개 인덱스 행을 읽어 집계했고, RE2-OB 90건 모두 로그·트레이스 존재 플래그가 참이었다. 인덱스 접근과 최소 20건의 **메타데이터 가용성**만 확인했다. 인덱스만 확인한 당시에는 텔레메트리 다운로드, 파일 무결성, 접근 권한, 변환 호환성 및 blind export 실행을 확인하지 않았다. Phase 1 검증 결과는 리뷰 기록을 참조한다. 인덱스 `case`, `root_cause_service`, `fault`와 원본 경로는 정답을 포함하므로 평가자 전용이다. 실제 데이터 다운로드 및 실행은 별도 수동 단계다.

[공식 RCAEval agent 가이드](https://github.com/phamquiluan/RCAEval/blob/main/docs/AGENTS.md)에 따르면 blind export는 익명 case 디렉터리와 `task.json`, 메트릭·로그·트레이스 파일을 제공하고 answers JSONL은 작업 디렉터리의 형제에 둔다. 후보는 task의 candidate_services 및 candidate_indicators로 제한하며 predictions JSONL의 `case_id`, `ranks`를 채점한다. upstream 문서는 최신 main 기준이며, 현재 프로젝트의 선택적 PyPI 1.7.0 휠에는 해당 CLI가 없는 것으로 이전 확인됐다. 실제 실행 전 CLI가 포함된 **고정 버전**, 의존성, 원본 형식/Parquet 호환성, 라이선스 및 20건 부분집합 채점 경로를 검증해야 한다. 무작정 전체 데이터나 labels를 agent에 제공하지 않는다.

## 조사 흐름과 계약

[LangGraph](https://docs.langchain.com/oss/python/langgraph/overview)를 상태 기반 오케스트레이션으로 사용할 계획이다. 각 노드는 명시적 입력·출력과 오류를 반환하고 실행기는 상태 전이와 예산을 검사한다. 모델·그래프·도구는 테스트에서 교체할 수 있어야 한다.

1. **조사:** case_id, 허용 후보, 시간 범위 및 이용 가능한 신호를 확인하고 필요한 조회를 요청한다. 모달리티 부재와 빈 결과를 구분해 기록한다.
2. **가설 생성:** 관측된 증거를 참조하여 허용 후보의 가설을 생성한다. 후보 외 문자열이나 존재하지 않는 evidence ID는 거부한다.
3. **증거 검증:** 각 가설의 근거가 동일 case의 성공한 조회에서 유래하고 ID·시간·후보와 연결되는지 검사한다. 근거가 없으면 추가 조사 또는 불충분한 증거 종료로 전이한다. 참조 존재는 인과성이나 주장과 근거의 의미적 일치를 증명하지 않는다.
4. **순위화:** 검증된 근거가 있는 후보만 중복 없이 순위화한다. 모든 항목에 설명과 최소 하나의 유효 evidence ID가 필요하다. 제출 전에 기존 계약으로 최종 검증한다. 오류·예산 소진·근거 부족 시 실패 envelope를 반환하고 정상 순위를 꾸며내지 않는다.

상태에는 case_id, 후보, 도구 호출 및 종료 상태, 불변 evidence registry, 가설·검증 결과, 사용량과 한도, 결과/오류를 포함한다. 도구 호출은 감사 가능하게 유일 ID와 성공·실패, 인자, 시작·종료 및 요약을 기록하되 정답·비밀은 기록하지 않는다. 외부 작업과 영구 상태 저장은 기본값이 아니다.

### 조회 도구 인터페이스 (설계)

공통 요청: `case_id`, 허용된 `service` 또는 `indicator`, `start`, `end`, 선택적 필터와 페이지/결과 한도. 시간은 UTC epoch seconds, 시작 포함·종료 제외, `start < end`; task 데이터 범위 밖 요청과 경로/임의 파일 접근은 거부한다. 응답은 `call_id`, `status` (`ok`, `empty`, `unavailable`, `error`), 자료 유형, 적용된 범위·필터, 잘림 여부, 결과와 evidence ID/provenance를 포함한다. 실제 최대 반환량과 시간 범위 정책은 미정이며 승인 전 실환경 실행 금지다.

| 도구 | 추가 인자 | 응답 내용 |
|---|---|---|
| `query_metrics` | indicator, 집계 방식 및 시간 구간 | 관측 시계열 또는 명시된 집계와 단위 |
| `query_logs` | 서비스, 선택적 검색 필터 | 시간과 출처가 포함된 로그 항목 |
| `query_traces` | 서비스, 선택적 상태·지연 필터 | 시간·서비스·span 관계 및 지연 요약 |

각 evidence에는 ID, case_id, call_id, 유형, 자료 출처 및 범위, 검증 가능한 결과 참조를 붙인다. 입력의 정적 evidence와 성공한 조회 결과만 등록한다. 같은 ID의 상충 payload, 다른 case, 실패/빈 조회에서 만들어진 ID는 거부한다. 본 명세의 데이터 구조와 상세 스키마는 구현 단계 계약 변경 시 테스트와 함께 구체화한다.

## 격리 및 실행 제한

[격리 정책](../evaluation-isolation.md)을 따른다. 평가자는 원본·인덱스·정답·표본 매핑을 보관하고, 에이전트는 익명 blind 작업 디렉터리만 읽기 전용으로 받는다. 부모·원본·정답·결과 채점 파일·평가자 환경 변수를 노출하지 않는다. OS 또는 컨테이너 권한으로 강제하고 실제 접근 거부를 별도 테스트한다. 도구는 허용된 파일만 제공하고 심볼릭 링크·경로 이탈을 거부한다. 네트워크, 외부 도구 및 로깅은 최소 권한이며, 공개 데이터 역매칭과 악의적 누출 가능성을 별도로 다룬다. 기존 문자열 탐지기는 방어 보조 수단이며 격리의 증명이 아니다.

도구 호출 최대 횟수 및 LLM 비용 한도는 **미정**이며 값·적용 범위(케이스별/전체), 동시성, 토큰 상한, 재시도와 과금 오차 처리 역시 결정되지 않았다. 실제 LLM/실데이터 평가는 이 정책과 모델·가격·중단 방식을 결정하고 설정 및 테스트에 반영하기 전 실행하지 않는다. 향후 승인된 한도는 호출 전에 검증하고 실패·재시도도 카운트하며, 사용량 미확인이나 예산 추정 불가능 시 fail closed한다. 호출 후 비용은 공급자 청구나 반환 사용량으로 정산하며, 미리 예측한 한도만으로 실제 청구 초과가 불가능하다고 보장하지 않는다.

## 평가 지표 및 수락 기준

- **Top-1/Top-3:** 고정된 20건 중 정답 서비스가 각각 첫 1/3개 결과에 있는 케이스 수 ÷ 20. 누락·실패·미제출은 miss로 계산하고 coverage(제출 수/20), 오류 유형을 별도 표시한다. 단, malformed/중복/unknown case JSONL은 upstream이 거부하므로 실행 자체를 실패로 보고 수정 후 재채점한다. 서비스 점수와 indicator 점수는 분리한다. indicator가 정답이 없는 경우 해당 집계에서 제외하고 분모를 별도 표시한다. 정확도 임계값은 **미정**, 측정 전 통과라고 주장하지 않는다.
- **근거 유효성:** 제출된 모든 순위 항목이 1개 이상의 같은 case에 등록된 성공 조회/입력 evidence ID를 가져야 한다. 없는 ID, 교차 case, 실패 호출 근거, 후보 밖 원인 및 빈 근거는 계약 검증 실패다. 구조적 유효성만 검증하며 의미적 뒷받침과 인과적 정확성은 별도 평가가 필요하다.
- **오프라인 수락:** 기존 테스트가 통과하고, mock으로 정상 흐름·도구 부재·도구 오류·한도 소진·빈 근거·가짜 ID·교차 case·유출·후보 오류·JSONL 오류 및 실패 envelope를 검증한다. 검증 규칙 제거/우회 시 음성 테스트가 실제로 실패해야 한다. 실데이터/모델/API 키 없이 `make check`와 `make harness-verify` 및 CI를 통과한다.
- **실환경 수락 전제:** OS 격리 거부 검증, 실제 20건 자료·버전 및 변환 확인, 승인된 정책과 비용/호출 제어 검증, scoring parity 확인. 실패 사례는 비밀을 제거한 synthetic fixture와 기대 결과로 재현하고 회귀 테스트에 추가한다. 실제 데이터나 정답을 저장소에 커밋하지 않는다.

## 미해결 결정 및 단계별 계획

1. **결정·데이터 준비:** 비용·호출·동시성·저장 정책 및 표본 배분 세부·시드, 실제 데이터 다운로드와 보관 위치, 실행기 버전, 점수 목표를 결정한다. 다운로드·자료의 완전성·20건 고정·격리 환경을 별도 검증한다.
2. **계약 및 실패 경로:** 각 도구·evidence·실패 envelope의 스키마와 테스트를 먼저 설계하고 기존 파서와 어댑터의 호환성 및 경계 조건을 검증한다.
3. **오프라인 그래프:** 모의 도구와 모의 모델로 흐름·예산·재시도·증거 검증을 구현하고 보안·회귀 테스트를 실행한다.
4. **격리 및 수동 평가:** 승인된 범위에서만 격리를 실제 검증하고 수동 평가를 실행한다. 모델·데이터 리비전·고정 표본·코드·사용량·결측·지표·실패를 기록한다. 성능 임계값이 정해지기 전에는 측정치만 보고한다.
5. **리뷰:** 계약 회귀, 입력·정답 격리, 재현성, 비용 및 지표 근거를 검토한다. 변경 사항은 명세·테스트·문서에 함께 반영한다.

## Phase 1 구현 경계

`python -m rca_agent.phase1 download`는 고정 리비전의 인덱스와 새 비공개 20건의 네 파일만 명시적으로 내려받고, `export`는 시간·식별자를 변환한 사본을 익명 폴더에 쓴다. 정확한 사용법은 README에 있다. 출력 `task.json`은 메트릭 열 이름을 후보로, 주입 시각과 자료 존재를 메타데이터 evidence로 변환한 기존 RCAInput 계약이다. 이는 upstream `rcaeval-agent`의 `task.json`이나 정식 채점기 입력과 동일하다는 뜻이 아니며 향후 parity 검증이 필요하다. 파일명 제거 및 복사는 보안 경계가 아니다. 컨테이너 격리 전 에이전트로 실행하지 않는다. 원본 telemetry의 의미적 단서, 공개 데이터 역매칭 및 하드링크·권한·정보 흐름 전반은 보장하지 않는다.

## 공식 RCAEval 상호운용성 수락 기준 (2026-11-08)

평가자는 고정된 공식 RCAEval 소스 버전에서 exporter 및 scorer를 별도로 실행한다. 선택 인덱스와 비공개 매핑을 대조한 후 Parquet를 평가자 전용 임시 원본 구조의 CSV로 변환하고 공식 exporter가 만든 manifest·task·telemetry만 blind 영역으로 옮긴다. 공식 answers 및 기존 Phase 1 ID ↔ 공식 ID ↔ source 매핑은 평가자 전용으로 둔다. 세 ID 집합에 중복·누락·변조가 있으면 중단하며, 번호가 같다는 사실만으로 동일 사례로 간주하지 않는다. 기존 입력 어댑터는 공식 task의 정규화된 service/indicator 후보를 합친다. 예측은 기존 RCAResult 계약과 case별 허용 후보·근거를 통과한 뒤 공식 ID 및 JSONL로 변환한다. 공식 scorer를 명시적으로 실행하고 실패를 그대로 전달한다. 공식 소스 커밋과 Python 환경을 고정·기록하며 네트워크·실제 모델 호출 없이 실행한다.

오프라인 회귀는 정규화·ID 일대일 대응·틀린 ID와 후보·근거 거부·정답 파일 격리·오류 전파를 확인한다. 추가 수동 통합 검증은 실제 20건에서 공식 exporter·toolkit·scorer와 서비스/지표 점수를 비교한다. oracle 기반 fixture는 채점기 정확성 검증일 뿐 RCA 분석 성능이 아니다. CSV 변환은 값 및 행을 보존하도록 검증하되 공식 원본 CSV와의 동등성은 별도로 확인하기 전 주장하지 않는다.

2026-11-08: 위 호환 계층을 구현해 실제 20건에서 공식 exporter·toolkit·scorer와 합성 양성 대조를 검증했다. 기존 Phase 1 독자 형식은 그대로이며 공식 형식은 별도 export다. 평가 상세 및 미검증 범위는 `reports/phase1-compatibility-verification.md` 참조.

## 블라인드 표본 보안 변경 (2026-11-09)

기존 seed 42 표본 및 그 ID는 공개 재구성이 가능하므로 블라인드 평가에서 폐기하고 이력 재현용으로만 보존한다. 사용자는 기존 20건과 겹치지 않는 새로운 RE2-OB 20건을 비공개로 선택하도록 결정했다. 선정·ID 부여에는 평가자 전용 암호학적 난수를 사용하고 seed와 실제 매핑은 에이전트와 Git에 공개하지 않는다. 기존 6개 유형의 균형과 서비스 편중 완화는 유지한다. 표본의 무작위화만으로 공개 원본 telemetry나 시간·고유 ID의 대조 공격이 차단된다고 간주하지 않는다. 시간 이동과 지정된 패턴 마스킹은 사용자가 승인했으며, 실제 격리 및 잔여 역매칭 가능성을 별도로 검증한다.

사용자 승인: 기존 공개 표본을 제외한 새 20건, 사례별 비공개 시간 이동, trace ID 가명화 및 로그 식별자 마스킹을 적용한다. 메트릭 등 원본 신호는 유지하고 네트워크 차단 등 격리와 잔여 위험을 명시한다. 무작위 표본 키와 원본-익명 대응은 평가자 전용으로 보관하며 기존 표본은 이력 확인용이다. 공개 원본 자체와 신호의 지문 대조까지 차단했다는 보장은 하지 않는다. 개인정보 마스킹은 명시된 패턴에 한정하며 완전한 비식별 보장이 아니다.

## Phase 2 승인된 조회 정책 (2026-11-11)

사용자는 조회당 최대 100건과 사례 데이터 범위 내 시간 조회를 승인했다. 시간 경계는 시작 포함, 끝 제외다. 모델 호출·LangGraph·정답 접근은 범위 밖이며 공식 RCAEval 채점기와 Phase 2 결과의 호환성은 미검증이다. 20건의 blind 데이터에서 메트릭 스키마는 15종, 로그·트레이스는 각 1종이었고 조사한 필수 열의 null은 없었다. 도구는 사례별 실제 스키마를 읽는다.
