# RCA v0.1 명세 초안

상태: 제안된 계약. 제품 범위와 평가 정책은 아직 승인되지 않았으며 이 문서는 v0.1 개발 승인이나 성능 목표를 뜻하지 않는다.

## 목적과 경계

관측된 증거와 허용된 후보를 입력받아 근거가 연결된 순위 결과 및 도구 호출 이력을 반환할 수 있는 RCA 인터페이스를 정의한다. 이 bootstrap은 계약만 검증하며 RCA 추론, LangGraph, 모델 호출, UI, 실데이터 어댑터 및 점수 계산은 구현하지 않는다. 구체적인 입력 데이터 종류, 후보 생성, 모델, 비용·요청 한도, 보존 정책과 정확도 목표는 미정이다.

## 계약 및 수락 기준

- 입력은 비어 있지 않은 case_id, 고유 candidate 목록 및 고유 ID와 내용을 가진 evidence 목록을 포함한다. 모두 명시적 JSON 필드이며 알 수 없는 필드는 거부한다.
- 결과의 case_id는 입력과 일치하고, 순위는 중복 없는 허용 후보를 하나 이상 포함한다. 각 순위에는 비어 있지 않은 설명과 입력에 존재하는 증거 ID가 하나 이상 있어야 한다. 도구 이력은 이름, JSON 객체 인수와 결과 요약을 보존한다. 빈 이력은 허용한다.
- JSONL은 행마다 JSON 객체 하나를 포함해야 한다. 빈 줄, 비정상 JSON, 중복 키 및 비표준 NaN/Infinity는 거부한다. 테스트는 고장 난 입력이 예외를 발생시키는지 검증한다.
- RCAEval 형식과 이 계약은 동일하지 않다. 추후 변환기는 RCAEval의 case_id와 ranks를 매핑하고 추가 근거를 공급해야 하며, 그 변환과 채점은 아직 미구현이다.
- `make check`는 로컬에서 모델/API 키 없이 lint, format, 전체 테스트 및 스킬 동기화를 확인한다. CI는 의존성 설치 후 같은 오프라인 검증을 수행한다. 네트워크 격리 자체는 테스트 코드의 보안 경계가 아니다.
- `make harness-verify`는 지침 일관성, lint, format, 스킬 동기화와 전체 테스트를 실행하고 테스트 실패 또는 skip을 거부한다. CLI 및 원격 CI 검증은 별도다. 검증기는 실패와 지침 불일치에 대한 자체 테스트를 갖는다.
- blind export 격리는 [평가 격리 정책](../evaluation-isolation.md)을 따른다. 실패 사례를 포함한 검사 통과가 실제 환경의 완전한 격리 또는 추론 품질을 증명하지는 않는다.

## v0.1 진입 조건

이 하네스 검증 성공 및 리뷰 후, 미정인 제품 범위, 데이터·평가 기준, 외부 호출과 비용 한도 및 실제 격리 방식을 사용자가 결정해야 한다. 결정 사항은 구현 전에 이 명세와 해당 설정에 기록한다.
